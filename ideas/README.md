## 怎样使用这个想法箱

1. **记录。** 每个想法一个 Markdown 文件，说明构想、希望带来的价值，以及想听大家讨论的问题。暂时不清楚的地方可以直接写“待讨论”。
2. **分享与讨论。** 把文件链接发到志愿者群。大家可以在群里交流，不需要每个人都操作 GitHub；之后由整理者把主要意见补充进记录，不默认公开姓名或聊天原文。
3. **整理共识。** 保留支持意见、顾虑和待解决问题，区分“有人建议”与“大家已经认可”，不把沉默当作同意。
4. **认可后立项。** 方向得到认可后，再确认牵头及参与意愿、基本范围和资源，另行准备正式项目资料，并从原想法文件链接过去。记录想法本身不触发执行。

可以继续讨论、调整、合并或暂缓一个想法；没有马上开展，也不等于没有记录价值。

## 新想法的简单格式

```md
# 💡 想法名称

**状态：** 待讨论，尚未立项
**记录日期：** YYYY-MM-DD

## 一句话构想
想做什么？

## 希望带来的价值
希望帮助谁、改善什么？

## 初步想法
有哪些可能的做法？不确定的内容标为待讨论。

## 想听听大家的意见
有哪些问题、顾虑或需要补充的地方？

## 讨论记录
尚未讨论。后续整理时区分建议、共识与未决事项。
```

## 公开分享边界

这是公开目录。这里只放适合对外分享的构想和经过整理的讨论摘要，不放私人联系方式、成员名单、聊天截图、未经授权的个人经历、私人群二维码或敏感内部安排。需要保密的内容应留在适当的内部协作空间。
