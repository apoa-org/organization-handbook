# APOA 数字资产登记与交接清单 V0.1

**状态：讨论草案，尚非董事会批准制度。** 本文用于盘点与交接准备，不作为账户权属、合同许可、当前访问权限或支付义务的最终证明。

## 一、基本原则

> **APOA 的数字资产属于组织，而不属于任何一任 Director、志愿者或技术服务商。组织应确保相关资产、数据、管理权限及技术文档能够持续维护和有序交接，不因个人离任或服务关系终止而中断。**

这里的“属于组织”主要指 APOA 的域名权益、业务资料、获授权的品牌和内容、会员及活动数据，以及依法依约可持有或使用的系统与代码权利。第三方软件、服务商自有服务器、个人既有代码等，不因用于 APOA 工作而自动转为组织所有；其授权、导出、迁移和持续使用权应在合同或书面交接记录中明确。

**一人可以建设，组织必须能够接手。** 决策可以改进，执行可以更换；接任者应能够知道系统在哪里、谁有权操作、怎样恢复、怎样撤销离任权限。

## 三、公开登记与私密登记分开

- **公开 GitHub：** 仅保存资产类别、对外链接、组织责任角色、权属状态（已确认／待确认）、审查日期及非敏感交接流程。
- **受限登记：** 保存真实账号、平台客户编号、授权人员名单、主机/邮箱管理入口、续费凭证、备份位置、数据分类、紧急联系人及合同。
- **独立的凭据保管：** 密码、2FA 恢复码、API token、SSH 密钥、数据库连接串和加密密钥只存放在经过批准的密码管理或秘密管理系统中，**不得**放入公开 GitHub、普通会议纪要、聊天群或未加密附件。
- 对受限登记的读取、修改、移交应有授权与记录。会员个人信息遵循适用的隐私、保留及安全要求。

| 字段 | 填写要求 |

| 合同、许可、费用、到期日 | 以发票和合同为准 |
| 数据类别、备份、恢复测试日期 | 涉及个人信息时列出处理限制 |
| 迁移／导出方式 | 所需文件、数据库、DNS、邮箱与依赖关系 |
| 最近核验日期、状态和待办 | 负责人、证据与下次复核日期 |

## 五、日常管理与重大变更

1. 由 APOA 指定一名数字资产负责人和一名替补。技术服务商负责约定的日常运维，不能代替组织作出权属与授权决定。
2. 重大操作——域名转移、删除重要数据、变更生产主机、组织级管理员权限及关键服务停用——须按 APOA 适用授权程序审批并留痕。
3. 至少两名适当授权的人员应能依托组织控制的恢复渠道处理突发离任、失联或账户锁定；不是互相共享同一个密码。
4. 每次技术交付留下变更记录；定期确认备份可恢复，记录测试日期、结果与问题。
5. 每年至少核对一次资产清单；负责人、供应商、域名／主机续费和重大系统调整时同步更新。

## 六、离任或服务商更换交接清单

- [ ] 确认董事会／授权代表接收人、交接日期、范围和必要审批。
- [ ] 逐项盘点资产，明确组织拥有、第三方许可、供应商自有和待争议项目。
- [ ] 在受控渠道转移／验证管理员与恢复权限；**接收者实际登录验证**。
- [ ] 交付完整可用的 WordPress 文件、数据库、媒体、代码及必要的部署说明；明确第三方许可范围。
- [ ] 提供域名/DNS、邮件服务、定时任务、插件、API、支付／订阅依赖清单。
- [ ] 验证备份及恢复；开展迁移演练或提供可验证的恢复记录。
- [ ] 将发票、合同、续费提醒和服务支持联系人移交授权人员。
- [ ] 由接任人确认服务可正常运行，并在安全窗口撤销原负责人不再需要的权限、轮换相关凭据。
- [ ] 将完成、未完成和风险事项形成书面交接记录；保留必要审计证据。

**紧急离任：** 组织首先保护数据、域名和关键业务的持续性；按事先批准的紧急授权程序接管、备份、调整权限，并事后补记决策，不应依赖私人账户登录共享。

## 七、Popcat 服务安排（建议，尚未批准）

据现任管理人员提出，拟从 **2027-01-01** 起由 Popcat 向 APOA 提供网站托管及基础技术维护，原则上以成本为主计费，并按实际服务情况出具合规发票。

- APOA 对网站业务数据、已获授权的内容与品牌资产保有独立控制与迁移能力；服务商保有其自有基础设施和明确约定的知识产权。
- 服务范围、价格、服务等级、备份恢复、数据处理、安全事件响应、责任限制、退出交接及案例展示许可，均须书面约定。
- 因拟议服务商与在任 Director 存在利益关系，应披露、回避适用的审批决策，并由无利益冲突的适当授权人员审议和留存记录。
- **现有主机已付款不等于 APOA 已承担费用。** 2027 年前的自愿投入与此后可能发生的商业收费分别记录，不追认未经批准的支出。
- 官网作为 Popcat 的公开案例须取得 APOA 授权；不得公开会员数据或安全细节。

此节只记录讨论中的方案，**不代表合同成立或已获董事会批准**。

- **影响：** 微信打开 APOA 官网部分链接时出现“Unable to confirm the security of this page. Visit carefully.”安全提示，影响微信群分享文章的直接阅读。此提示本身不构成网站实际违规的证据。

- **官方结果：** 2026-11-11 下午收到微信团队“Result: Successful”通知，确认该文章链接不含违规内容，并已恢复微信内直接访问。
- **后续验证：** 管理人员进一步抽查 APOA 其他官网链接，均可在微信正常打开；截至当日无需继续逐篇申诉。**该抽查不等于微信承诺永久将整个域名列入白名单。**
- **留档与复查：** 微信成功通知截图作为运维佐证，记录于受控工作资料中；本公开清单不载具体验证内容或账户凭据。验证 TXT 文件已按当次要求部署，后续按平台要求复核保留必要性及清理时机。如再次出现提示，先复测不同页面和账号，再通过微信站长验证与申诉渠道处理。
