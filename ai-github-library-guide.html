数字内容制作 · 入门实践指南 · 2026-10-28

不会编程，也能用 AI 和 GitHub 制作数字图书馆

从一篇文章开始，学习制作、发布和维护自己的数字内容。

这不是编程教材，也不是某个组织的项目介绍。跟着本文完成一次练习，你就能把自己写的一篇文章变成公开网页，并理解怎样让别人协助更新。

01｜GitHub 是什么，普通人为什么值得了解？

假如你准备把学习笔记整理成一个公开网站，最初只有三篇，半年后变成三十篇。有人帮忙改错字，有人更新资料链接，还有人希望保留旧版本。你需要的不只是一个可以放文件的地方，还需要清楚的修改记录。

GitHub 是用于存储文件、跟踪变化和组织协作的平台，建立在 Git 版本控制系统之上。它最常用于软件项目，但文字资料、网页和说明文档同样可以使用。它并不自动保证资料正确：资料是否可靠，仍要靠作者和编辑核查。

先记住三个词：Repository（仓库）是一组项目文件；Commit（提交）记录一次修改及其说明；GitHub Pages 是把仓库里的静态网页发布给读者的服务。GitHub 负责保存与协作，Pages 负责展示网页。

02｜先决定：WordPress、网盘，还是 GitHub？

如果只想发布个人博客，WordPress 的可视化编辑通常更直接。如果想和朋友共同写一份文档，在线文档或网盘可能更方便。如果希望把文章、网页代码、修改历史和公开协作流程一起长期维护，GitHub 就很有价值。

需求WordPressGitHub + Pages
编辑文章可视化后台较方便以文件为中心，初学者需要适应
修改历史有修订版本功能Git 提供细致的提交历史
多人提出修改通过角色、插件或工作流实现可使用 Issue、Pull Request
静态公开知识库可以适合
会员、付款、数据库可通过相应功能实现Pages 本身不提供后台处理

因此不是“GitHub 比网站好”。GitHub 本身也是网站服务。真正的选择是：你需要一个方便日常发文的内容管理系统，还是一个便于版本管理、公开协作和发布静态网页的工作流程？两者也可以配合使用。

03｜动手前，弄清网页由什么组成

制作一个最简单的网页，只需要一个 index.html 文件。HTML 决定标题、段落和链接；CSS 决定字号、颜色和布局；JavaScript 可以实现字号切换等交互。初学者不必一次学完三种语言。

先建立一个名为“我的小图书馆”的文件夹，准备一篇自己有权公开的短文章，标题、正文和一个来源链接即可。请不要使用包含个人隐私的笔记，也不要直接复制受版权保护的整篇文章。

04｜让 AI 把文章制作成网页

把你自己写的文章交给 AI，试着输入下面这段指令：

请将以下文章制作成一个完整的单文件 HTML 网页，文件名为 index.html。要求：适合手机阅读；保留全部正文和来源链接；支持调节字号；中文语义化标题；不加载外部字体或图片；不添加我没有提供的事实。请先给出代码，再说明如何保存和预览。

把 AI 返回的代码保存为 index.html。在电脑上用浏览器打开这个文件，就可以先预览。若网页出现乱码，检查文件是否保存为 UTF-8 编码。若 AI 漏掉段落、改写了引文或加入未经核实的资料，应返回要求修正，而不是直接发布。

一个最小网页示例：

<!doctype html>
<html lang="zh-CN">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>我的小图书馆</title>
</head>
<body>
  <h1>我的小图书馆</h1>
  <p>这是我的第一篇学习笔记。</p>
</body>
</html>

05｜在 GitHub 保存你的第一份网页

注册或登录 GitHub。在网页上选择新建仓库（New repository），取一个容易记住的英文名字，例如 my-reading-library。如果打算公开阅读，选择 Public；这意味着仓库中的内容和历史记录可能被任何人看到，上传前务必检查隐私与版权。

创建仓库后，可以通过网页的 Add file → Upload files 上传刚才的 index.html，填写一句提交说明，再确认提交。这样你已经拥有一个保存网页源文件及其修改历史的地方。

之后若要更正文字，可在 GitHub 网页中打开文件、选择编辑，再提交一次。打开 History 或 Commits 就能查看修改记录。界面名称可能随 GitHub 更新略有变化。

06｜用 GitHub Pages 把文件变成网址

进入仓库 Settings → Pages，在 Build and deployment 中选择从分支部署（Deploy from a branch）。选择放有 index.html 的分支（例如 main）以及根目录（/root），保存设置。等待发布流程完成后，Pages 页面通常会显示访问网址。

对名为 my-reading-library 的普通项目仓库，典型地址形如 https://你的用户名.github.io/my-reading-library/。这是地址结构示例，并不是已经创建的网站。首次发布可能需要一些时间；如果访问失败，先查看 Pages 设置与 Actions 中的部署状态。

把网址发给朋友，他们就能阅读，而不需要登录 GitHub。需要注意：GitHub Pages 发布的是公开静态内容，不适合放密码、个人资料、私人文件，也不提供完整的会员或支付后台。

07｜怎样让更多人一起更新？

当网站只有你一个人维护，直接修改文件就够了。人数增加后，最好先建立简单的编辑规则：每篇资料写明作者或编辑、来源链接、更新日期；未经核实的事实不能当作结论；重要改动先审阅再发布。

不懂 GitHub 的参与者可以通过邮件或约定渠道提供更正建议。熟悉 GitHub 的人可以提交 Issue（问题与建议），或使用 Pull Request（请求项目维护者审核一组文件修改）。Pull Request 不是自动发布：维护者可以讨论、要求修改，决定是否合并。

一个实际分工例子：甲找官方来源，乙用 AI 起草中文导读，丙对照原文核查，丁检查手机排版并发布。这只是协作方式示例，不是必须设立四个职位。

08｜常见问题与容易踩的坑

AI 做好的网页就一定能用吗？不一定。至少检查正文是否完整、链接能否打开、手机上是否溢出、字号按钮是否工作，以及是否出现虚构内容。

GitHub 免费就没有限制吗？不是。Pages 有使用政策、构建和资源限制；实际额度与条款应以 GitHub 官方说明为准。

能把网上找到的文章整篇搬进去吗？不能仅因为网上公开就认为可以转载。优先提供原始链接，使用自己撰写的摘要，必要引文应遵守版权要求。

是不是所有人都必须注册 GitHub？不是。阅读公开 Pages 无需账号；直接提交 Issue、Pull Request 或编辑仓库通常需要登录。也可以由编辑代为整理非技术参与者的建议。

这适合正式机构网站吗？要看需求。静态知识页面可以，涉及身份验证、个人数据、复杂互动或交易时，需要额外系统与安全设计。

09｜给自己安排一个一小时的小实验

第一步，写一篇 200—400 字、确认有权公开的学习笔记。第二步，请 AI 生成单文件 HTML，检查后在浏览器预览。第三步，建立 GitHub 仓库并上传。第四步，启用 GitHub Pages。第五步，找朋友在手机上试读，记下问题，再提交一次修改。

完成以后，你会真正理解：文章是内容，HTML 是阅读页面，GitHub 保存修改，GitHub Pages 让网页公开。下一次只要继续增加文章与目录，就能逐渐形成一个数字图书馆。
