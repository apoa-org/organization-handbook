第 1 章

GitHub 是什么？

GitHub 像一间有历史记录的公共工作室。仓库是资料柜，提交（Commit）是修改记录，分支（Branch）是独立工作台，Pull Request 是请别人检查修改的申请。它不只属于程序员，也适合保存公开知识。

第 2 章

APOA 图书馆怎样建成？

先选题和查找官方来源，再由 AI 协助整理、翻译和排版，人工核对后制作 HTML 阅读页。源文件存放在 organization-handbook 仓库 main 分支的 community-library/reader 目录；发布文件放在 gh-pages 分支，通过 GitHub Pages 供公众阅读。

第 3 章

为什么不直接放在官网？

WordPress 官网适合会员、活动、报名和新闻发布；GitHub 适合开放资料的多人修改、版本记录和审核。两者可以互相链接。GitHub Pages 主要适合静态网页，不适合直接存放私人会员数据或处理支付。

第 4 章

不会 IT，怎样参与？

你可以只推荐一个权威资料链接；也可以请 AI 帮你写一页中文导读，再交编辑核实；还可以注册 GitHub 账户，通过 Issue 提建议，或通过 Pull Request 提交修改。完全不需要先学会命令行。

第 5 章

怎样请 AI 帮忙？

试着对 AI 说：请将这篇澳大利亚官方资料整理为普通中文读者能理解的学习卡。写明机构、标题、日期和原文链接；不要编造事实；将非官方翻译明确标记；有疑问请标记待核对。AI 能加速写作，但不能代替人工核实。

第 6 章

第一次共建实验

任选一项：找出一个错字、推荐一个可靠来源，或者整理一张 200 字学习卡。将资料和来源交给编辑人员，经过核对才发布到公开书架。每次修改都会在 GitHub 留下历史记录。
