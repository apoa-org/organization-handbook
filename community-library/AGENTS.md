# APOA 社区图书馆｜AI 编辑与出版工作说明（AGENTS.md）

> 适用于 `community-library/` 的文章创作、修订、来源核查与阅读网页发布。更新于 2026-10-28。新对话或 AI 助手：**先读本文件，再读对应现有文章和来源，不要凭记忆直接重写。**

## 1. 项目与发布位置

- 公开阅读网站：https://apoa-org.github.io/organization-handbook/
- GitHub 仓库：https://github.com/apoa-org/organization-handbook
- 内容与网页源文件：`main` 分支的 `community-library/reader/`
- 当前发布：`gh-pages` 分支根目录的同名 HTML 文件
- 图书馆当前仍在 organization-handbook 仓库中；**未来可能迁移独立仓库，但未实施前不得假定已经迁移**。
- 组织手册（治理制度、正式决议、公司资料）与社区图书馆（公众学习资料）必须区分。图书馆文章不是 APOA 已批准的政策。

## 2. 写给谁、写成什么样

面向在澳大利亚生活、希望了解非营利组织、社区参与、志愿服务、治理、物业及其他公共知识的中文读者。中文优先，英文术语和来源可追溯。读者不需要预先掌握专业术语。

**文章要有内容，也要好读。** 不要只堆定义、口号或五个每段只有一两句话的小节。优先采用：
1. 一个具体、贴近读者的问题或场景开头；
2. 解释关键概念、适用边界和常见误区；
3. 分节展开，给出具体情境、可操作例子或对比；
4. 说明与 APOA 社区工作可能有什么关系（标明是应用思考，而非已批准措施）；
5. 读完可以思考或尝试什么；
6. 文末保留可靠英文来源、版本/日期、链接与免责声明。

**手机晨读优先：** 一般学习文章以读者早晨拿起手机、约 10–15 分钟内能读完为目标；多数文章可参考约 1,500–2,500 个中文字，按题材灵活调整，不以凑字数为目的。开头 30 秒内给出具体问题与阅读价值，正文段落简短、避免同义重复，通常控制在 4–6 个主要小节（复杂题材可例外）。来源、版本、声明集中放在文末，正文只保留必要的出处提示。既要具体扎实，也不把一条简单标准扩写成冗长说教。

篇幅以信息密度和题材需要为准，不机械追求字数。避免“赋能、共创美好未来”等空泛套话；也不要为了生动虚构事实。可参考现有 `engagement-pyramid.html` 的深入程度，但**它的六层模型只适用于那篇文章**。

## 3. 事实、来源与专业内容（必须遵守）

- **先查原始资料**：澳大利亚优先 ACNC、ASIC、AICD、Volunteering Australia、Fair Work Ombudsman、政府部门、相关法规/监管机构及可信的专业机构；具体题材选择相应一手来源。
- 每项重要事实、数字、法律义务、标准版本和引述都要能追溯到相应来源。检查页面是否仍有效，标注发布/修订日期与查阅日期（可核实时）。
- 严格区分：**官方英文原文／官方发布的译本／APOA 非官方中文译读／编辑者的学习解读／APOA 的应用思考**。不能把 AI 解释说成监管机构原话，也不能把行业最佳实践写成强制法律。
- 不得擅自断言 APOA 已取得某种认证、通过某项制度、实施某个项目、持有某种税务或慈善身份。涉及 APOA 的正式状态，回查组织手册及最新官方记录。
- 人物故事只使用原始采访或公开报道可证实的经历、人物细节和引述。**不能编造对话、心理活动、具体日期、经历或成果**。必要时明确“据报道”“作者的学习思考”。
- 专业主题须解释适用范围、例外和不确定性；法律、财务、税务、医疗等内容不得冒充个别专业意见。
- 尊重版权：优先链接完整原文；只使用必要的短引文，不上传或翻译转载受版权保护的全文。图片须确认使用权、署名及来源。
- 找不到可靠来源时，写明未核实，或先暂停相关断言；**绝不补造引用或链接**。

## 4. 编辑标准：把“空洞”改成“丰满”

优先修复：只有概念没有解释；只有鼓励没有实例；用抽象话重复标题；没有交代为何重要；人物故事缺少已知的生活细节；读者看完不知道怎样理解或使用。

可补充：具体场景、因果关系、反例、常见误解、适用条件、社区中的实际选择、对照表或可访问的网页示意图。

不应补充：无来源的案例或数字、想象出来的人物细节、未经授权的 APOA 制度、没有依据的法律结论。对于已足够扎实的文章，**不为了扩写而扩写**。

文章应尊重不同参与方式，不给志愿者按热情或时间投入划分人格价值；参与深度、正式职位和法定治理权限不是一回事。

## 5. HTML 阅读体验

- 优先复用现有文章的页面结构、视觉规范、页眉页脚、返回导航及来源区，不擅自改动已封板的首页和书架设计。
- 保留中文朗读、字号调节、手机端阅读、语义化标题与链接、键盘可访问性。
- 图表优先使用**响应式 HTML/CSS 或可访问的 SVG**，同时提供文字说明；不要用一张字太小的海报代替正文。不要随意生成或替换 APOA 官方 Logo。
- 新文章必须有清晰标题、导语、分节正文、英文术语、出处及声明；链接使用可长期访问的相对路径或官方 URL。
- 更新文章时检查标签闭合、CSS 和脚本不冲突、手机布局与中文朗读文本完整。

## 6. GitHub 工作流与验收

1. 读取本 AGENTS.md、`community-library/PUBLISHING-CHECKLIST.md`、目标文章、对应来源以及 `community-library/CONTRIBUTING.md`（如适用）。
2. 先说明将修改哪些文章及理由；用户要求直接执行时可以直接制作。
3. **先在 `main` 的 `community-library/reader/<slug>.html` 更新源文件**，核查页面内容与现有功能。
4. 经确认可发布后，将同一文章同步至 `gh-pages` 根目录的 `<slug>.html`；注意两个分支的路径不同。
5. **每次发布必须执行 [上新与发布同步检查清单](PUBLISHING-CHECKLIST.md)**：正文、书内目录、主题书架、首页「最近更新」、首页「书架里有什么／新书」及相关链接均要检查并按需同步；新书必须成为独立馆藏，不能只出现在首页或书架外的临时推荐。首页/书架既有 UI 不因新增文章而随意重设计。
6. 提交记录写清楚文章与改动范围。结束时报告：已改文件、是否发布、链接、仍需人工核查的问题。**未实际提交时，不得声称已更新网站。**
7. 不修改无关的组织资料、正式政策、财务记录或其他仓库。

## 7. 给新 ChatGPT 对话的简短开场

> 我们在维护 APOA 社区图书馆。请先阅读 https://github.com/apoa-org/organization-handbook/blob/main/community-library/AGENTS.md ，再查看目标文章的 GitHub 源文件和英文原始资料。按该规范写一篇中文优先、专业可信、具体好读的学习文章。请明确区分官方来源、中文解读与 APOA 应用思考。先给我完整文章草稿；只有我明确要求发布时，才更新 GitHub 的 main 与 gh-pages。不要更改已封板的首页和书架 UI。

## 8. 维护说明

本文件是**编辑工作约定**，不是法律文件或 APOA 正式治理政策。新对话不会自动获得所有历史上下文；请提供本文件链接及具体写作题目。若将来图书馆迁入独立仓库，应同步迁移并更新此文件中的路径与发布规则。
